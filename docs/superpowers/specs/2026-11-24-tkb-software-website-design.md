# เว็บไซต์ TKB Software — เอกสารออกแบบ

วันที่: 2026-11-24 · เจ้าของ: KAWIN (TKB CON Co.,Ltd.)

## 1. เป้าหมายและเหตุผล

KAWIN พัฒนาโปรแกรมแบบติดตั้งในเครื่อง (Standalone, Windows) หลายตัว และต้องการเว็บไซต์สำหรับนำเสนอและแจกตัวทดลองใช้ ให้ดูน่าสนใจและน่าเชื่อถือ

เมื่อเจ้าของกิจการเข้ามาที่เว็บ สิ่งที่อยากให้เขาทำคือ **ดูคลิปแนะนำ** และ **ดาวน์โหลดไปทดลองใช้** ของโปรแกรมที่สนใจ แล้วติดต่อผ่าน LINE เมื่อพร้อมซื้อ เว็บไม่ได้ขายหรือรับชำระเงินออนไลน์

## 3. Goals / Non-goals / Anti-goals

**Goals**
- หน้าแรกแสดงโปรแกรมทั้งหมดเป็นการ์ด, หน้ารายละเอียดต่อโปรแกรม
- หน้ารายละเอียด: คลิปแนะนำ, จุดเด่น, ภาพหน้าจอจริง, ปุ่มดาวน์โหลดทดลองใช้, ปุ่มแอด LINE, สเปกเครื่องที่ต้องการ, วิธีติดตั้ง
- ก่อนดาวน์โหลดต้องกรอก **ชื่อ + เบอร์โทร** → บันทึกพร้อมชื่อโปรแกรม → ได้ลิงก์ไฟล์ติดตั้ง
- เพิ่มโปรแกรมใหม่ได้ง่ายเมื่อพร้อม

**Non-goals**
- ไม่มีราคา/ตะกร้า/ชำระเงินออนไลน์
- ไม่มีบัญชีผู้ใช้ฝั่งลูกค้า
- ไม่ทำกลไกลิขสิทธิ์ (อยู่ในตัวโปรแกรม + license-server แล้ว)
- ไม่ทำเดโมออนไลน์

**Anti-goals** (ถ้าเป็นแบบนี้ถือว่าล้มเหลวแม้จะใช้งานได้)
- ดูเป็นเทมเพลตทั่วไป ไม่น่าเชื่อถือ
- ลูกค้างงว่าหลังดาวน์โหลดต้องทำอะไรต่อ
- เว็บพังแล้วกระทบระบบลิขสิทธิ์

## 4. เส้นทางลูกค้า (ตกลงแล้ว)

1. ดูคลิป / จุดเด่น
2. กด "ดาวน์โหลดทดลองใช้" → ฟอร์ม ชื่อ + เบอร์โทร → ได้ลิงก์ไฟล์ติดตั้ง
3. ติดตั้ง → โปรแกรม **เริ่มทดลองใช้ 30 วันเองทันที** (กลไกที่มีอยู่แล้วใน license-server: เก็บชื่อร้าน/เบอร์ตอนเริ่มทดลอง)
4. หมดอายุ → โปรแกรมล็อก → ติดต่อ LINE @793lptfr / 085-977-4474 เพื่อซื้อลิขสิทธิ์ถาวร

ปุ่ม LINE บนเว็บ = สอบถาม/ซื้อลิขสิทธิ์ (ไม่ใช่ขั้นบังคับเพื่อเริ่มทดลอง)

หน้าเว็บต้องบอกชัดตั้งแต่ปุ่มดาวน์โหลดว่า "ดาวน์โหลดฟรี ทดลองใช้ 30 วัน"

**ก่อนตัวติดตั้งพร้อม:** ปุ่มดาวน์โหลดแสดงเป็น "ลงชื่อรับแจ้งเมื่อพร้อม" ใช้ฟอร์มเดียวกัน (ข้อเสนอของ Claude ที่ KAWIN ไม่ได้คัดค้าน)

การ์ด "เร็ว ๆ นี้" (โรงแรม, HR): แสดงเป็นสีเทา + ปุ่มแอด LINE รับแจ้งเตือน, ไม่มีหน้าดาวน์โหลด

## 5. หน้าตา (เลือกแบบ A แล้ว)

สะอาด มืออาชีพ พื้นขาว โทนน้ำเงิน
- แถบบน: โลโก้ TKB Software ซ้าย · เมนู โปรแกรม / วิธีติดตั้ง / ติดต่อ ขวา
- Hero: ซ้ายเป็นหัวข้อใหญ่ + บรรทัดรอง + ปุ่มหลัก "ดาวน์โหลดทดลองใช้" + ลิงก์ "ดูคลิป"; ขวาเป็นภาพหน้าจอ POS
- ใต้ Hero: การ์ดโปรแกรม 3 ใบ — ตัวพร้อมใช้มีกรอบเน้นสีน้ำเงิน, ตัวเร็ว ๆ นี้เป็นเทา
- ภาษาไทยทั้งเว็บ, รองรับมือถือ (เจ้าของร้านจำนวนมากเปิดจากมือถือ แต่ดาวน์โหลดบนคอม — หน้าในมือถือควรมีทางให้ส่งลิงก์ไปเปิดบนคอม เช่นปุ่มคัดลอกลิงก์/ส่งเข้า LINE ตัวเอง: ข้อเสนอของ Claude)

จุดขายของ POS ที่ใช้เป็นเนื้อหา (จาก README ของโปรเจกต์): POS ยิงบาร์โค้ด/ราคาปลีก-ส่งปนในบิล, ขายได้แม้เน็ตหลุด, สต๊อก + ตรวจนับด้วยมือถือ, ลูกค้า/ขายเชื่อ/วงเงิน, ซื้อเข้า/เจ้าหนี้/แนะนำสั่งซื้อ, รายงาน + Dashboard ส่งออก Excel, ใบเสนอราคา, พร้อมเพย์ QR, สิทธิ์ผู้ใช้ 5 ระดับ, ฐานสินค้าตั้งต้น 16,880 รายการ

ยังไม่มีคลิปและภาพหน้าจอ — ใช้ภาพหน้าจอจากระบบจริงเมื่อมี; ระหว่างนี้ใช้ช่องว่างแทน (placeholder) และส่วนคลิปซ่อนได้ถ้ายังไม่มี

## 6. แนวทางที่พิจารณา

1. **Next.js แยกเว็บ บน Vercel + เก็บรายชื่อใน Supabase โปรเจกต์เดียวกับ license-server** — **เลือกแล้ว**: ใช้เครื่องมือที่ KAWIN ใช้อยู่ (Next.js 15, Tailwind, Supabase, Vercel), รายชื่อผู้ดาวน์โหลดอยู่ฐานเดียวกับเครื่องที่ติดตั้งจริง เทียบได้ว่าใครโหลดแล้วไม่ติดตั้ง; แลกกับต้องดูแลเว็บเพิ่มอีกตัว
2. รวมหน้าเว็บในแอป license-server — ไม่เลือก: เว็บพังแล้วระบบลิขสิทธิ์ล่มด้วย
3. HTML + Google Form/Sheet — ไม่เลือก: รายชื่อแยกจากข้อมูลติดตั้ง ฟอร์มไม่กลมกลืน

## 7. ข้อกำหนดทางเทคนิค

- เว็บเป็นโปรเจกต์ใหม่แยก (เช่น `C:\dev\tkb-software-web`), Next.js 15 App Router + TypeScript + Tailwind CSS 4, deploy บน Vercel
- รายชื่อผู้ดาวน์โหลด: ตารางใหม่ใน Supabase โปรเจกต์ license-server (ข้อมูลเดิม: `installs`, `license_events`, เปิด RLS ไม่มี policy)
  - บันทึกฝั่งเซิร์ฟเวอร์ (Route Handler / Server Action) ด้วยกุญแจฝั่งเซิร์ฟเวอร์เท่านั้น เหมือน license-server — ไม่ใช้ anon key จากเบราว์เซอร์
  - ฟิลด์อย่างน้อย: ชื่อ, เบอร์โทร, product, เวลา
- ไฟล์ติดตั้ง: ขนาดคาดว่าหลายร้อย MB (รวม Node + PostgreSQL + PostgREST) → ไม่เก็บบน Vercel/Supabase; ใช้ Cloudflare R2 หรือ GitHub Releases (การเลือกระหว่างสองตัวนี้เป็นของผู้สร้าง) เว็บส่งลิงก์ให้หลังกรอกฟอร์ม; ยอมรับว่าลิงก์แชร์ต่อได้ เพราะทุกเครื่องยังต้องลงทะเบียนกับ license-server
- ข้อมูลส่วนตัว (PDPA): ฟอร์มเก็บชื่อและเบอร์ ต้องมีข้อความแจ้งวัตถุประสงค์ + ช่องยินยอม และหน้านโยบายความเป็นส่วนตัว
- ติดต่อ: LINE @793lptfr, โทร 085-977-4474 (จาก README โปรเจกต์ POS)

## 8. การดูรายชื่อผู้ดาวน์โหลด (ตกลงแล้ว)

- ทุกครั้งที่มีคนกรอกฟอร์ม ระบบส่งข้อความแจ้งเข้า LINE ของ KAWIN (ชื่อ, เบอร์, โปรแกรม, เวลา) ผ่าน LINE Messaging API ของ LINE OA — ถ้าส่ง LINE ไม่สำเร็จ ข้อมูลต้องยังถูกบันทึกและลูกค้ายังได้ลิงก์ดาวน์โหลด
- ดูรายชื่อย้อนหลังใน Supabase dashboard — ไม่มีหน้า admin บนเว็บในรอบนี้
- ผู้ลงชื่อ "รับแจ้งเมื่อพร้อม": KAWIN แจ้งเอง ไม่มีระบบส่งอัตโนมัติ
